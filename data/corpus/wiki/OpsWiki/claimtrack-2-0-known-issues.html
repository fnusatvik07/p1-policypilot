Status at issue: Active
Owner: Darnell Price, Manager, Operations Training

Purpose

This page captures recurring ClaimTrack 2.0 behaviors and the approved workarounds used by Disputes Operations when processing claims in ClaimTrack, CardView, and the Corvane portal. It is intended for Claims Intake, Debit & EFT Investigations, Credit Card Investigations, Chargeback Recovery, and QA reviewers who need to complete daily work without delay while the system migration stabilizes.

ClaimTrack 2.0 launched with automated deadline clocks. Use the steps below whenever a case presents one of the known issues listed on this page. Do not create duplicate work items unless the original case is unrecoverable.

[!NOTE] ClaimTrack 2.0 is the system of record for dispute case management beginning 2023-06-05. If the case is visible in an older queue or legacy view, process it in ClaimTrack 2.0 and use the legacy screen only for reference.

Before you start

[!IMPORTANT] Confirm you are using the correct customer profile and claim type before editing any deadline, assignment, or status field. ClaimTrack 2.0 will recalculate due dates after each save.

Common issues tracked on this page - Claim deadline clock appears one business day ahead of the worksheet. - Attachment upload succeeds, but the document list does not refresh immediately. - Status changes in ClaimTrack do not always match CardView until the case is re-opened. - Corvane response codes may display after a short delay when a network chargeback is filed. - Work items can briefly appear in both the old and new queue views during the first open/save cycle.

Known issue handling steps

1) Deadline clock does not match the case worksheet

  1. Open the claim in ClaimTrack 2.0.
  2. Select Case Summary and review the Deadline Clock field.
  3. Open the associated worksheet from the case attachments or the Disputes Ops Library reference copy.
  4. Compare the worksheet date to the ClaimTrack date.
  5. If the ClaimTrack date is correct, continue processing and add an internal note: deadline clock verified against worksheet.
  6. If the worksheet reflects the earlier case logic, confirm whether the claim was migrated from the legacy DOP-2xx record set.
  7. Do not overwrite the ClaimTrack date unless you have validated the issue against the case facts and the applicable procedure.

2) Attachment upload does not refresh on screen

  1. In ClaimTrack 2.0, open the case and go to Evidence.
  2. Select Upload Document and attach the file.
  3. Wait for the upload confirmation banner.
  4. If the new item does not display, select Refresh Case once.
  5. If the document still does not display, save the case, close it, and re-open from the queue.
  6. If the attachment remains missing after re-open, verify whether the file is visible in the case audit trail before re-uploading.

[!TIP] Do not upload the same file multiple times while the list is lagging. Duplicate attachments slow review and make QA reconciliation harder.

3) CardView and ClaimTrack show different account status

  1. From ClaimTrack, open the Account Details section.
  2. Launch CardView from the case action menu.
  3. Compare the card status, available balance, and recent transaction list.
  4. If CardView appears more current, keep both screens open and continue using CardView for servicing reference.
  5. Return to ClaimTrack and save only after you have confirmed the case note, status, and assignment fields.
  6. If the discrepancy affects a debit, credit, or prepaid dispute decision, follow the governing procedure in the relevant CPS-SOP document before finalizing the case.

4) Corvane chargeback response is delayed

  1. Open the case in ClaimTrack 2.0.
  2. Select External Processor and confirm the case is routed to Corvane Card Services.
  3. In the Corvane portal, review the chargeback file status.
  4. If the response code is pending, leave the case in the current queue and set a follow-up reminder.
  5. Recheck the portal after the case refreshes in ClaimTrack.
  6. Once the Corvane response posts, update the dispute outcome and continue with the normal recovery or investigation path.

[!WARNING] Do not manually close a Corvane-linked chargeback case while the portal response is pending. Allow the processor status to post before completing the file.

5) Queue assignment briefly flips after save

  1. Open the case in ClaimTrack 2.0.
  2. Review the assigned queue and owner.
  3. Make the required update.
  4. Click Save once.
  5. If the queue flips back to the prior value for a few seconds, wait for the page to finish refreshing.
  6. Confirm the final queue value before routing the case onward.
