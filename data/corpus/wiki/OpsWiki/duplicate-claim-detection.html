Duplicate claim detection

Created by Darnell Price · Last updated 2023-06-05 · Version 2

WI-037 — Duplicate claim detection

Type: Work instruction
System(s): ClaimTrack 2.0, CardView, Corvane portal
Owner: Darnell Price, Manager, Operations Training
Version: 2
Effective / issued date: 2023-06-05
Status at issue: Active

Purpose

Use this procedure when a customer submits a new dispute claim and there is a possibility that the same transaction, account, or event has already been claimed. Duplicate claim detection prevents duplicate case creation, duplicate case handling, and duplicate customer communication.

This page supports the claim intake workflow in ClaimTrack 2.0 and should be used together with CPS-SOP-201 Claim Intake (All Channels) and CPS-SOP-223 Duplicate and Repeat Claims.

[!NOTE] This work instruction covers intake screening only. If the claim is already open, escalated, or resolved, follow the applicable dispute procedure and do not create a second case.

Before you start

Check Action
Required access Confirm you have access to ClaimTrack 2.0, CardView, and the Corvane portal.
Intake facts Gather customer name, account number, transaction date, amount, merchant name, and last four digits of the card or account.
Search scope Check open, pending, and recently closed claims for the same customer and transaction.
Documentation Keep all search results and notes in the case record.

[!WARNING] Do not rely on customer memory alone. Duplicate detection must be based on system records, transaction details, and case notes.

Procedure

  1. Open ClaimTrack 2.0.
    Sign in to ClaimTrack and select Claims Intake from the left navigation. Confirm the claim queue is set to the correct intake channel before you begin the search.

  2. Search for the customer.
    In the Customer Search panel, enter the customer’s last name and one additional identifier, such as account number or card number. Select Search.

  3. Review matching cases.
    In the results list, review all cases tied to the same customer. Pay particular attention to cases with:

  4. the same transaction date,
  5. the same merchant or card network reference,
  6. the same amount, and

  7. the same dispute reason.

  8. Open each possible match.
    Select the case number to open the record. Review:

  9. case status,
  10. dispute type,
  11. claimed transaction details,
  12. notes from prior associates, and

  13. any references to withdrawal, replacement, or re-filed disputes.

  14. Check CardView for account-level activity.
    Return to the customer profile and open CardView. Confirm whether the transaction appears on the card ledger and whether any prior dispute indicators, temporary credits, or reversals are present.

  15. Check Corvane portal for network disputes.
    If the claim involves a debit, credit, or prepaid card transaction routed through Corvane, open the Corvane portal and search by card number and transaction date. Review whether a network chargeback, representment, or earlier dispute record exists.

  16. Compare the transaction identifiers.
    Compare the following across ClaimTrack, CardView, and Corvane:

  17. transaction date and posting date,
  18. amount,
  19. merchant name,
  20. authorization or retrieval reference, and

  21. partial card number.

  22. Determine whether the claim is a duplicate.
    Treat the claim as duplicate when the same event is already open or previously handled and no new transaction is identified. If the claim is partially overlapping but contains a new transaction, process only the new item and note the overlap.

  23. Document the outcome in ClaimTrack.
    Add a case note stating the duplicate match source, the matching case number, and the system(s) reviewed. Use clear language such as “duplicate of prior claim” or “partial overlap; new item remains open.”

  24. Route the claim as required.
    If the claim is a duplicate, follow the disposition in CPS-SOP-223 and do not create a new investigation path. If the match is unclear, escalate the case for review using the normal intake escalation queue.

[!TIP] When two claims share the same merchant and date but different amounts, confirm whether one amount is a partial approval, split tender, or a separate cardholder event before marking a duplicate.

[!TIP] Search spelling variants and merchant abbreviations. A duplicate may not appear under the exact same merchant name shown by the customer.

[!WARNING] Never delete a claim record to remove a duplicate. Keep both records visible in ClaimTrack and document the disposition in the appropriate case.
