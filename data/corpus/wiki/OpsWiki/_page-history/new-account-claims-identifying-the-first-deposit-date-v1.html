WI-023 — New account claims: identifying the first deposit date

Type: Work instruction
Status: Active
Effective/Issued: 2017-04-01
Version: 1
Owner: Darnell Price, Manager, Operations Training

Purpose

Use this procedure when a claimant states that a newly opened deposit account had an unexpected or disputed transaction before the first deposit was posted. The first deposit date is the anchor point for confirming account activity, routing the claim correctly, and determining whether the account was in normal funding status at the time of the alleged event.

This work instruction is used by Claims Intake and, when needed, by Debit & EFT Investigations and Credit Card Investigations for cross-channel review.

[!NOTE] Before you start

Have the following available: - Claim number in ClaimTrack - Customer name and account number - Opened date, if already captured in the claim record - Access to CardView and Corvane Card Services portal - The deposit account screen in HLX Core

If the account is not a checking or savings account, or if the transaction type is not a deposit-account issue, stop and route the case under the applicable claim procedure.

Procedure

  1. Open the claim in ClaimTrack.
    1.1 Sign in to ClaimTrack and search by claim number.
    1.2 Open the claim summary.
    1.3 Confirm the product type and affected account number.

  2. Review the account opening details.
    2.1 In the claim notes, identify the account opening date entered by the intake associate.
    2.2 If the opening date is missing, use the customer profile to retrieve the date opened from the linked deposit account record.
    2.3 Add a note stating the source of the opening date.

  3. Check for the first posted deposit in HLX Core.
    3.1 Launch HLX Core from the customer profile link or by account number search.
    3.2 Open the transaction history for the deposit account.
    3.3 Sort transactions by posted date in ascending order.
    3.4 Locate the first deposit transaction that posted to the account.
    3.5 Record the posted date and amount.

  4. Validate against CardView when a debit or card-linked claim is involved.
    4.1 Open CardView from the claim record or by card number lookup.
    4.2 Confirm whether the card was activated before the first deposit date.
    4.3 Review the card activity timeline for any authorization, settlement, or reversal events that occurred before funding.
    4.4 Note whether card activity pre-dated the first deposit.

  5. Check Corvane Card Services for processor-side activity.
    5.1 Open the Corvane Card Services portal.
    5.2 Search by card number or case reference.
    5.3 Review the processor history for the earliest transaction event.
    5.4 Compare the processor event date with the first deposit date in HLX Core.
    5.5 If the processor shows activity before the first deposit date, capture the event type and timestamp in ClaimTrack.

  6. Document the first deposit date in ClaimTrack.
    6.1 Update the claim note with the first deposit date, time if available, and source system used to verify it.
    6.2 State whether the first deposit occurred before or after the disputed transaction.
    6.3 Attach any screen prints only if required by the claim’s evidence handling instructions.
    6.4 Save and close the claim task.

  7. Escalate exceptions.
    7.1 If the deposit history is unavailable, appears incomplete, or conflicts across systems, send the claim to the appropriate investigation queue.
    7.2 Include the account opening date, first deposit date, and all source screens reviewed.

[!TIP] When the first deposit date is the only missing fact, check HLX Core first. In most cases, that record is the controlling source for deposit posting history.

[!WARNING] Do not assume that account opening date and first deposit date are the same. A newly opened account may remain unfunded for several days, which can change how card or ACH activity is interpreted.
