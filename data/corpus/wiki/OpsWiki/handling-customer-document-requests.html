Handling customer document requests

WI-022 — Handling customer document requests

Type: Work instruction
System(s): ClaimTrack 2.0, CardView, Corvane Card Services portal
Owner: Darnell Price, Manager, Operations Training
Effective / issued: 2023-06-05
Status at issue: Active
Version: 2

Purpose

Use this page when a customer requests copies of documents connected to a disputes case, including claim notes, transaction records, correspondence, and related evidence maintained in ClaimTrack, CardView, or Corvane Card Services. This work instruction supports CPS-SOP-214 — Customer Requests for Investigation Documents and the notice requirements in CPS-SOP-230 — Customer Letters and Notices.

This version reflects the move to ClaimTrack 2.0, including automated deadline clocks and revised case navigation.

Before you start

Before you start

  • Confirm the customer is authorized to receive the documents.
  • Confirm the request is tied to an existing dispute, claim, or billing-error case.
  • Confirm you have the correct claim number, card number, or customer profile.
  • Review any access restrictions, legal holds, or third-party sensitivities before release.
  • If the request is unusual, incomplete, or potentially escalated, pause and route per CPS-SOP-214.

Procedure

1. Locate the case in ClaimTrack 2.0

  1. Open ClaimTrack 2.0.
  2. Use the global search bar to search by claim number.
  3. If the claim number is unavailable, search by card number, customer name, or open date.
  4. Open the case summary and verify:
  5. product type
  6. claim status
  7. assigned queue
  8. customer contact information
  9. Select the Case Files tab, then open Documents.
  10. Review the case file to identify what is already stored in ClaimTrack versus what must be retrieved from CardView or Corvane.
  11. Check the deadline clock in the case header and note whether the request is tied to a time-sensitive customer notice.

Tip

In ClaimTrack 2.0, the deadline clock is system-generated. Use it as a reference point, but continue to follow the procedure in CPS-SOP-210 — Investigation Timelines and Extensions for case handling decisions.

2. Determine the document set

  1. Identify the exact items requested by the customer.
  2. Match the request to the case type and product:
  3. debit card disputes
  4. credit card billing error disputes
  5. prepaid disputes
  6. associated correspondence or notices
  7. Confirm whether the documents are available in ClaimTrack attachments or must be retrieved from an operational system.
  8. If the request includes card-level data, continue to CardView.
  9. If the request includes processor-level chargeback evidence, continue to Corvane Card Services.

Warning

Do not release internal analyst notes, workpapers, or third-party materials unless the case file and applicable procedure clearly permit release. If there is any uncertainty, escalate before sending documents.

3. Pull card details in CardView

  1. Open CardView.
  2. Search using the customer’s card number or masked card reference from ClaimTrack.
  3. Verify the following against the case record:
  4. card status
  5. last four digits
  6. product type
  7. posting date of the disputed transaction
  8. Open the transaction history.
  9. Locate the relevant transaction(s) and capture the screen print or export, following your team’s standard naming convention.
  10. Return to ClaimTrack 2.0 and attach the CardView output to the case.

Tip

Use the transaction date and amount together when validating the record. Merchant name alone is not sufficient when multiple similar items post in the same cycle.

4. Retrieve chargeback or network evidence in Corvane

  1. Open the Corvane Card Services portal.
  2. Search the case using the dispute reference or card number.
  3. Open the dispute record and review available evidence packages.
  4. Download only the requested materials and confirm they correspond to the correct transaction and cycle.
  5. Save the file in the approved case folder and attach it to ClaimTrack 2.0.

Warning

If the Corvane package contains more than the customer requested, stop before release and verify whether any items must be withheld under the applicable request scope.

5. Prepare the customer package

  1. Review the final document set for completeness.
  2. Remove any unnecessary internal routing information.
  3. Confirm the package reflects the correct claim and customer identity.
  4. Update the ClaimTrack notes with:
  5. date of request
  6. systems reviewed
  7. documents prepared
  8. any exceptions or escalations
  9. Send the approved document package through the designated customer delivery channel.

6. Close out the request

  1. Mark the request complete in ClaimTrack 2.0.
  2. Add a concise case note stating the request was fulfilled or escalated.
  3. If the request could not be completed, document the reason and route the case to the appropriate queue.
  4. Retain all source files and attachments according to CPS-SOP-229 — Claim Records and Evidence Retention.
